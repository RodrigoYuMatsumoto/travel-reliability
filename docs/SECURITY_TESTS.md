# Security verification scope

Passing the automated suite is not an exhaustive security assessment or a production certification. All test inputs are synthetic. No family evidence is used.

| Boundary                         | Executed regression evidence                                                                                                                                                                                     | Limits                                                                                                                  |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Authentication and authorization | `tests/api.test.ts`, `tests/oidc.test.ts`, `tests/security.test.ts`: workspace isolation, viewer permissions, collaborator revocation, decoded routes, origin/CSRF checks, PKCE/state/nonce and replay rejection | OIDC protocol tests use synthetic provider responses; a deployed identity provider still requires validation            |
| Encrypted records and exports    | `tests/core.test.ts`: authenticated ciphertext bound to its workspace, offline bundle round trip and tampering rejection                                                                                         | No independent cryptographic implementation audit; operator key management remains essential                            |
| Evidence lifecycle               | `tests/security.test.ts`: expiry before private reads, source-owned derivative erasure, rollback and durable cleanup retry                                                                                       | Does not establish erasure from external backups or all fleet-scale race behavior                                       |
| Hostile documents                | `ingest/tests/test_extract.py`, `test_html_safety.py`, `test_fuzz_regressions.py`: passive text, hidden HTML, archive traversal, bounded MIME trees, attachment exclusion and text/pixel limits                  | Bounded mutations are not exhaustive parser fuzzing; arbitrary hostile PDFs and dependency exploits are not proven safe |
| Optional model                   | `tests/llm.test.ts`, `tests/reference-improvements.test.ts`: unsupported claims/tool calls rejected, literal source matching, bounded repairs, interrupted-run handling, conservative outbound screening         | Marker and schema checks cannot guarantee detection of every prompt injection or personal identifier                    |
| Webhooks                         | `tests/security.test.ts`: workspace-specific credentials and replay receipts                                                                                                                                     | Real provider configuration and operational key rotation need separate verification                                     |
| Browser and privacy              | `tests/browser/trip.spec.ts`: real browser workflow and private API data excluded from the offline cache; source/history scanner; npm SBOM omits optional author/contact fields                                  | Automated accessibility and privacy scans have limited coverage and are not proofs of compliance                        |
| Dependencies and infrastructure  | npm audit, locked Python runtime pip-audit; CI runs real PostgreSQL/Redis/S3 tests, native OCR and both container builds                                                                                         | No known advisory at audit time does not mean no vulnerability; built images are not a hardened deployed service        |

## Current executed evidence

Version 0.3 expands to eight roles, 52 commands and seven read-only MCP tools. The real SDK tests load every declared role/command and preserve legacy names. Local verification passed 142 TypeScript tests, 17 Python tests, four browser tests and the 54 authenticated DAST assertions. Three durable-service cases and one native OCR case require the CI services. The source-derived coverage and semantic-review limits are recorded in [agent audit](AGENT_AUDIT.md).

The v0.3 TypeScript mutation campaign added catalog, domain-aware intake, checkpoint preparation and expense settlement to the nine existing families: 13,000 executions per seed, two seeds, zero remaining findings or infrastructure errors, stable source fingerprints. The oracle separately checks exact shares, prior internal payments, residual settlement and absence of external effects. These counts do not imply unique inputs, coverage-guided fuzzing or evaluation of a host LLM. The Python runtime is unchanged and remains exercised by recurring CI.

`priorSettlements` is mandatory: an explicit empty list means no known prior payments; omission is not zero. Transfer history and allocation acceptance are declarations, not banking confirmation or payment authority. Checkpoint counters/capabilities are caller-reported bookkeeping, not a tamper-proof global quota or host sandbox. Archive verification now checks complete catalog distribution, fixed paths, per-file hashes and relative links in both portable ZIPs.

## Historical v0.2 evidence

Version 0.2 adds a local MCP frontier and an agent-first instruction package. The six real stdio protocol tests cover modern/legacy clients, four tools, fixed resources/prompts, unrelated caller directories, unknown names and extra arguments, UTF-8/EOF/depth/size/burst limits and generic diagnostics. Phase-aware intake tests keep incidents, refunds, existing group expenses and new planning separate; accepting an unaccompanied minor's declared composition does not establish travel eligibility.

The local security campaign used Semgrep CE 1.183.0 with the security-audit and OWASP top-ten rulesets, plus Bandit 1.9.4. Metrics/source upload were disabled. The final local sweep had no remaining scanner findings; one precisely documented B108 suppression concerns only a sandbox HOME hint, not an opened predictable file. Static review confirmed and corrected diagnostic amplification; explicit GCM tag length was defense in depth, not a demonstrated forgery.

Dependency advisories [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) and [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) affected the static-file dependency graph. Until the parent package updates its declared range, precise overrides select `glob` 14.0.3 and `minimatch` 11.0.3; static serving, traversal rejection, builds and browser tests are rechecked. This avoids the audit tool's incompatible parent downgrade suggestion. Audit results are time-dependent and are recorded by the current CI.

The mutation/property campaigns completed 18,000 TypeScript and 768 Python case executions across two deterministic seeds, without post-fix findings, infrastructure failures or source changes in the principal runs. These are case executions, not a claim of unique exploits or coverage-guided fuzzing. Native PDF parsing/rendering was exercised; native OCR was stubbed in fuzzing and remains tested separately. Historical startup/global-budget timeouts were triaged as inconclusive runs and replayed; they were not reported as clean passes or confirmed parser hangs. See [fuzzing scope](../security/fuzz/README.md).

The authenticated DAST harness executes 54 assertions over explicit HTTP calls, browser rendering and raw TCP probes against a newly created loopback-only memory store. It exercises access isolation, origin/CSRF controls, malformed/oversized requests, bounded diagnostics, prototype keys, stored markup, calendar delimiters, read-only roles and session revocation. It has no access to traveler records or live providers. The recurring workflow separately runs ZAP 2.17 against the unauthenticated synthetic public surface, requires observed active-rule traffic and blocks untriaged medium/high findings. A configured workflow is not execution evidence: completed CI reports are the authority for that scan. See [DAST scope](../security/dast/README.md).

Local v0.2 application recheck on 2026-10-30: 95 TypeScript tests and 17 Python tests passed, plus four desktop/mobile browser tests. Three durable-service tests and one native OCR test were skipped locally; the CI workflow provisions those dependencies and requires them. Thirteen persistent standard-library unittest regressions cover the audit gates themselves, including malformed/missing report fields, parser failures, missing active traffic and medium/high alerts. Neither an absent findings field nor a scanner timeout can become a clean pass. Both dependency audits reported no known vulnerabilities at the local recheck. The Python test-client dependency emits a deprecation warning.

For GitHub pull requests, the history scanner excludes only the identity metadata of the current platform-generated test merge, after validating the CI event/ref/SHA, HEAD, two parents and generated subject. It reports that exclusion by hash. Every file blob, every parent commit and real merge-commit metadata remain checked. Synthetic regressions reject a mismatched context, private file contents and private identities in parent history; there is no general email allowlist.

The live demo was also checked over actual HTTP and Chromium at both loopback addresses, including opening the synthetic trip. These checks distinguish a working application from simply having dependencies installed in an unrelated directory.

The first executed [v0.2 security run](https://github.com/RodrigoYuMatsumoto/travel-reliability/actions/runs/41153980284) was correctly blocked by ZAP rule 10055 (medium): Helmet inherited `font-src 'self' https: data:`. Explicit `fontSrc: ["'self'"]` removes the arbitrary HTTPS font source; an API regression and the authenticated header probe enforce the directive. The original scan observed 849 active-rule requests, so the finding was not inferred from configuration alone. The subsequent release scan must pass the same gate without a medium/high allowlist.

## Not completed

Independent penetration testing, exhaustive SAST/DAST or parser coverage, production TLS/IdP/storage configuration assessment, backup restore and backup erasure drills, fleet-wide load/abuse testing, key rotation exercises and incident-response drills. The bounded campaigns above do not complete those operational assessments or establish immunity to prompt injection. No claim that every security test has been performed is made. The application remains pre-1.0.
